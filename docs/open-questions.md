## Duplicant traits (2026-11-05)

Findings from transcribing `TUNING/DUPLICANTSTATS` into `packages/game-data/src/trait-info.ts`. None verified in game.

- **Exclusions on load.** Resolved from the decompile: the game does not enforce them. `Traits.OnSpawn` adds each saved trait ID that exists in `Db` and passes `Game.IsCorrectDlcActiveForCurrentSave`; only `MinionStartingStats.GenerateTraits` calls `AreTraitsMutuallyExclusive` and `AreTraitAndAptitudesExclusive`. The editor still blocks conflicts when adding, and never changes conflicting traits already in a save.
- **Trait model rules.** `GenerateTraits` returns early for a bionic after rolling one `BionicBug` and one `StartWith` booster trait, so the positive, negative, genetic and need lists are filtered out for bionics, and the bionic lists out for standard duplicants. For stress, joy, congenital and special traits no rule is known, so both models are allowed. In the fixtures `StressShocker`, `DataRainer` and `RoboDancer` occur only on bionics; whether a standard duplicant can use them is untested.
- **Booster traits.** A `StartWith<booster>` trait exists for each booster created with `isStartingBooster = true` (ten, listed in `trait-info.ts`). The game's strings also hold a `StartWithBooster_Carry1` entry, though Carry1 is not a starting booster in code; it is not offered.
- **Catalog gaps.** The extractor missed the congenital traits, the booster traits and the need traits (their strings live outside `STRINGS.DUPLICANTS.TRAITS`), and it title-cased `RoboDancer` into `Robodancer`, which the game would not recognise. `game-data` now adds the congenital and booster traits and corrects the ID. The need traits (`Claustrophobic` and others) stay out of the picker for lack of English strings; they appear in no fixture.
- **Unused strings.** `Anxious` and `Fussy` have strings but no `Trait` definition in `TRAITS.cs`, so the game skips them; the editor does not offer them.
- **Interests.** Mutually exclusive aptitudes are only checked against the new trait's list, as in the game: adding `CantDig` is blocked while a duplicant has the Mining interest, but turning Mining on for a duplicant with `CantDig` is not blocked yet.
